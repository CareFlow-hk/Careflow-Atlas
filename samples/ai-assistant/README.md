# AI 助手测试样本

这些活页簿用来测独立的「AI 助手」对话框（`docs/AI_ASSISTANT.md` 阶段 3）：
页首「AI 助手」→ 打字／放一份表（可同时）→ 按「上傳」→ 看「將執行的目標」→ 按一次「確認並執行」写入。
文字和文件可以一起上传；同一份清单、同一次写入（`docs/AI_ASSISTANT.md` 6.1）。

**全部是合成资料**：姓名是「陳大文（合成）」这类占位字，电话用重复数字（2111 1111），大厦是示范街的假楼宇。不要把真实住户资料放进这个资料夹，也不要把测试后的导出档放进来。

文件由 `scripts/make-ai-samples.ts` 产生，改动请改脚本再跑：

```bash
npm run samples:ai
```

脚本写完档会**重新读回文件**跑一次规则识别，确认每个样本仍落在预期的状态；侦测器口径一改，这里会直接报 FAIL，不会等到测试时才发现样本失效。

## 文件与预期

| 文件 | 规则识别 | AI 应该做什么 | 要看什么 |
| --- | --- | --- | --- |
| `01_機構自有探訪表.xlsx` | `AMBIGUOUS` | 提出楼宇／楼／室等字段对应，指出原表没有大厦编号 | 对话框提示规则识别认不出，但仍可请 AI 核；接着直接出「將執行的目標」，栏位对应收在折叠区可查 |
| `02_表頭含糊_欄位不足.xlsx` | `UNKNOWN` | 把楼／室／情况／住户／电话都提出来对应 | 只认得「日期」「同事」，其余靠 AI；没对上的栏会原样记在備註，不影响前面先看目标清单 |
| `03_與外展無關_工資表.xlsx` | `UNKNOWN` | **整份拒绝** | 只显示「與本項目無關，無法回答。」，不出现任何字段建议，也不出现目标清单 |
| `04_清單內格式_中文六表封存.xlsx` | `KNOWN` | 不被呼叫 | 对照组：对话框会说明「規則識別已認得」，正路是「紙本與 Excel」；直接汇入应显示「已識別」 |
| `05_含個人資料_外送預覽.xlsx` | `AMBIGUOUS` | 提出地址／楼层／单位等对应 | 外送预览要标出「地址、住戶姓名、電話、備註」四栏**不会送出**并显示「未送交 AI」；样本由第 2 列（表头）开始，标题列不送出 |
| `06_只有表頭_無資料.xlsx` | `UNKNOWN` | 只能依表头建议，不得虚构住户、楼层或日期 | 样本只有 1 行；目标清单不应出现不存在的资料，应说明没有任何一行可以写入 |
| `07_分塊測試_701行工資表.xlsx` | `UNKNOWN` | **第 1 段就拒绝，其余不再送出** | 701 行会分成 3 段；应该只看到第 1/3 段的忙碌文字，随后是「與本項目無關，無法回答。」。**Network 只有 1 个请求**，不是 3 个 |
| `08_超長儲存格_截斷.xlsx` | `UNKNOWN` | 正常提出栏位对应 | 外送预览要写「有 3 格超過 80 字，只送出前 80 字」；Network 里那 3 格确实只到 80 字。不能声称送了完整原文。**这份表没有「大廈」欄**，所以另外配一段文字「在裕安樓」一起上传：目标清单应出现「3 行沒有填大廈，都按你在補充說明寫的「裕安樓」處理」，3 行都可以写入（5樓 B室、5樓 C室、6樓 A室），**不会出现「不會寫入」的表格**；原表没有「覆蓋結果」欄，留空即可，写出的记录不带 `coverage`，不是「暫無可靠記錄」。不加这段文字时，每行都报「未填大廈」并进入下面的紧凑表格 |
| `09_欄數超上限_拒絕.xlsx` | **读取阶段拒绝** | 不被呼叫 | 65 栏（64 栏上限＋1）。应显示上限说明，整份档案不送出，**不得静默截掉第 65 栏**。注意：这句目前来自共用读取器，用语仍写「示範」（见下方「已知问题」） |
| `10_多工作表_只送一份.xlsx` | `AMBIGUOUS` | 只读「探訪紀錄」，另一张不碰 | 外送预览要写明「另 1 個工作表（工資（勿送））未送交 AI」；Network 请求体里**不得**出现任何工资金额 |

`KNOWN`／`CANDIDATE` 是规则识别已经处理好的结果，AI 只在 `UNKNOWN`／`AMBIGUOUS` 才会被询问 —— 这是刻意的封闭范围，不是功能缺失。

`09` 的「规则识别」栏写的是读取阶段的结果：`readWorkbook` 在超限时直接抛错，不会给出 `UNKNOWN`／`AMBIGUOUS` 这类状态。两种结果都属于正确行为（拒绝，而不是悄悄裁掉内容），脚本把它们放在同一个字段里比对。

## 已知问题

- **`09` 的拒绝文字是「每張示範工作表限 5000 列及 64 欄。」** 上传的是真实档案，却提示「示範」；而且 `src/ai/preview.ts` 自己那句更具体的说明（「請先分拆檔案」）轮不到执行，因为共用读取器先抛错了。数字口径一致（同为 5000／64），所以只是措辞问题，未修。

## 不在这批样本里的东西

模型**回应的形状**（例如 `REFUSE` 却附带栏位、非既有栏位代号、栏索引越界、多了合约以外的栏位）无法用文件触发 —— 送进去的内容决定不了模型怎么回。那几种由 `src/ai/contract.test.ts` 的单测用假回应锁定，不靠人手测。

## 每次测试都要确认的九件事

1. **外送预览和实际送出的内容一致**：F12 › Network，请求体里只有预览看到的那些行，没有预览里没列出的工作表，也没有标了「未送交 AI」的个人资料栏；预览的「共 N 行 · M 欄，將分 K 次送出」要和分块数一致，各块行数相加等于 N。
2. **没有按下写入就不会有资料变动**：文件只产生一份「將執行的目標」；只有按「確認並執行」之后记录才出现，且带「由 AI 協助」。
3. **栏位表只列 AI 认出与必须的栏**（2026-10-24）：其余收在「其他欄位（N）」里，展开后仍能指定；没对上的栏不用勾选，清单会写明「記在備註」，写入后打开记录应看到「原表「電話」：2111 1111」这样的文字。
4. **表中写到、工作区没有的楼层／单位**（2026-10-24）：「將執行的目標」会多出一行「在「裕安樓」新增「9F」這一層與「9F A室」」，与需要它的行一起写入（清单没有「这一行要不要写」的勾选框；「不會寫入」表格里的勾选框只用来批量补值）。按「確認並執行」后先建立、再写入。要测这一项，请用工作区已有的示范大厦（例如裕安樓）另外造一份带新楼层／单位的表；写成「頂樓」这类读不出数字的楼层仍应「未能採用」。
5. **失败讯息看得出是哪一层**：401／403 是密钥问题、429／402 是额度、网络失败、60 秒超时、格式作废，各有各的说法，不应一律显示「網絡錯誤」。
6. **分块不重复付费**（`07`）：一份非外展的大表，拒绝发生在第 1 段之后，Network 里只有 1 个请求；分段数与预览写的「將分 K 次送出」一致，但**拒绝之后不再继续**。
7. **不会写入的行改成紧凑表格，可点可批量补**（2026-10-25）：用 `08` 上传但**不配**「在裕安樓」，3 行都报「未填大廈」，展开「不會寫入的 3 行」应看到：一行一笔、每栏一个表头（大廈／樓層／單位／到訪日期／…／覆蓋結果），空的大廈格红框。先在「大廈」格直接填「裕安樓」，清单应立刻重判、该行移到上面的目标清单；再勾选剩下两行、选「大廈」、填「裕安樓」、按「套用到已選行」，两行一起变成可写入，并显示「已改 N 格（人手 N、AI 0）」。把值改回原样，改动消失。这些勾选框只用来选「套用到哪几行」，不是逐行确认写入。
8. **第二屏叫 AI 改**：用 `08` 配「在裕安樓」上传后（3 行已可写入），对对话说「這幾行都是已嘗試接觸」→ 行上标「AI 提議」、计数变成 AI 那一边，**写入前**记录历史不应有任何变动。对话里说「新增一行」或要求改姓名／电话栏，应整份被拒并说明原因。
9. **文字说明地点**：把表换成一份没有楼层／单位栏的表（或用 `08` 的副本删掉「樓」「室」两栏），文字写「在裕安樓 5 樓 B 室」→ 目标清单显示「N 行沒有填樓層／單位，都按…處理」，行落到 5F B室；文字同时写「5樓 B室 同 6樓 A室」时，不替人挑一个，并说明原因。
