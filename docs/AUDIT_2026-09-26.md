# CareFlow Atlas 全量审查与修复

审查日期：2026-09-26。对象为 `lhjlol/Careflow-Atlas` 的 `main`，基线 `f0a56ebbb36e896d755aa6317018d82f1c54b385`。修复在独立分支 `codex/downstream-audit` 上完成，没有把下游变更覆盖进 OscarXuHz 的工作区，也没有推送或部署到远程。

## 结论

原有 91 个测试全部通过，但不足以覆盖导入写入保护、更正链和真实浏览器兼容性。本轮通过失败复现、代码修复、自动测试、实际 Docker 容器和 Chromium 联合验证补齐了这些缺口。项目仍是合成数据前端原型；W0 的三个推测格式仍没有写入解析器。

## 已修复的问题

| 优先级 | 问题与触发条件 | 修复与证据 |
| --- | --- | --- |
| P1 | 改变字段或候选格式后，界面显示新映射，确认按钮却可写入旧的 pendingSnapshot | 任何映射修改都撤销待导入数据、基线和旧合并预览；说明整理原档后重新加载。浏览器实际验证按钮禁用且 localStorage 未写入 |
| P1 | CANDIDATE 字段或没有解析器的模板可通过写入检查 | 提交检查阻止候选、歧义和推测模板；识别支持英文枚举值，保留所有内置样例的正常导入路径 |
| P1 | 原更正分叉的两支再被更正后，原来的冲突检查不再发现分叉 | 统一检查所有直接更正边，不以中间版本是否失效来掩盖分叉；领域验证和导入使用相同规则 |
| P1 | 更正已结案的任务会重新产生待跟进；更正结案记录又被当作重复结案拒绝 | 沿更正链解析任务身份；只有有效结案记录参与计算；同一任务的不同版本不能被重复结案；显式撤销结案需写明更正原因 |
| P1 | 旧英文导入静默忽略未知列/工作表、重复表头和公式 | 有未处理内容时阻止整批导入，保留行列错误信息；新回归样例在原代码上全部失败 |
| P1 | 普通 HTTP 的 VPS 演示缺少 crypto.randomUUID，应用初始化可能白屏 | 使用 getRandomValues 生成符合 UUID v4 格式的随机标识作为兼容路径；不使用 Math.random；单测和浏览器验证缺少 randomUUID 时启动 |
| P1 | MapLibre <=6.4.0 包含第三方 attribution 清洗绕过漏洞 | 升至官方修复版本 6.4.1；Vitest 升至 4.1.11；最终 npm audit 为 0。实际使用的 style-spec 声明为直接开发依赖 |
| P1 | 升级 MapLibre 后 Vite 构建通过，但独立 worker 在运行时 404，地图不能完成加载 | 显式让 Vite 打包 worker 并设置地址；开发服务器和 Nginx 生产镜像均经过真实地图加载与楼层标签点击验证 |
| P2 | 空表头下的值或较后面的未知数据没有出现在识别警告中 | 按全部受限数据行扫描未知列，保留空白表头；同列被多个字段使用时标记歧义 |
| P2 | 旧英文工作簿按显示文本读取坐标造成舍入，同内置中文数据合并时误报冲突 | 改为读取原始值，回归验证精确坐标以及两种示例双向合并；浏览器验证街区扩展后再导入英文格式仍保留新历史 |
| P2 | 同一 Excel 的更正行移到原行前面就无法导入；空白行使错误/来源行号偏移 | 完整读取后验证更正引用，保留空白行的实际位置；排序与行号回归通过 |
| P2 | 中文解析器、识别器和旧英文解析器的输入上限不一致 | 共用 5 MB、5000 行、64 列的读取边界；超限明确拒绝，不截断后继续导入 |
| P2 | 待跟进被更正删除或结案关系被修改时，没有强制保存解释 | 改变跟进/结案关系须填更正原因；历史显示被更正状态，并与当前结案计算一致 |
| P2 | Docker 自检使用固定镜像/容器名，清理可能影响另一轮测试，构建参数镜像可能残留 | 每次使用独有名称和临时目录；清理只针对本次资源，日志和参数镜像纳入清理 |
| P2 | 使用可选反代认证时，公开的 Compose 8080 端口可绕过认证 | Compose 默认绑定 127.0.0.1；公开合成演示须显式设置 WEB_BIND=0.0.0.0，并更新部署说明 |

## 清理

- 更新过期的测试数量、MapLibre 版本，以及“更正尚未生效”的错误说明。
- 补充 W0 只提供预览、修改映射后需要重新加载的真实边界。
- 重写浏览器回归脚本：隔离上下文、核对完整持久化内容、验证旧数据不被改写；瓦片请求发出不再等同于成功加载。
- 保留原始合成工作簿、带格式的 mock 及归档副本；未用 SheetJS 重写这些人工制作的文件。
- 保留原工作区四个未提交文件；未顺带合入其中的地图镜头修改。

## 仍然存在的边界

- 手动字段映射是预览，三个推测格式不执行写入；本次选择明确阻止误写，没有扩展成通用 Excel 导入平台。
- 新验证会拒绝已存在但分叉冲突、或修改跟进关系却未注明原因的更正数据；原始 localStorage 内容会保留，不会自动删除或伪造原因。实际存量文件应先备份再核对。
- 不具备后端、认证、共享事务、真实机构数据治理或生产权限。localStorage 的多标签页并发写入仍不是事务，不适用于多人共享资料。
- 运行验证为 Apple Silicon / arm64 的本机 Docker 与 Chromium；未验证远程 VPS、amd64、真实 iOS/Android 或真实 NGO 工作簿。
- 文件/行列限制不等于 ZIP 解压炸弹或恶意工作簿完整防护；没有进行恶意压缩文件压力测试。
- Excel 依赖由识别面板静态引用，仍会在应用启动时加载；地图仍按需加载。低端设备性能需要单独测量。
- 原始部署历史保留为历史证据，当前结论以本轮检查为准。
