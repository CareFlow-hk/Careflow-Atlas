# 工作区加密（机构密语）

2026-10-19 起。目的：开启跨装置同步后，服务器（VPS）上存的住户资料只有机构的人打得开；VPS 管理员、云服务商、开发团队都看不到内容。

## 一句话版本

住户姓名、电话、备注、记录文字在**浏览器里**用机构的钥匙加密，服务器只收到密文。钥匙由「机构密语」锁住，密语只有机构同事知道，服务器从来收不到。

## 什么会加密，什么不会

| 加密（服务器只看到 `enc:v1:…`） | 不加密（服务器看得到） |
| --- | --- |
| 人员：姓名、电话、地址备注、联络备注 | 大厦名称和地址（公开街道资料）、楼层、单位、劏房 |
| 住户：户名；住户成员：关系；居住记录：位置备注 | 各种编号（id）、日期、覆盖状态、接触结果、住房判断等选项 |
| 到访：备注 | 谁录的（`createdBy`）、谁撤回（`deleted`）、跟进操作人 |
| 记录：备注、证据、自定义选项文字、跟进事项（做什么、谁跟、何时）、更正原因、纸本原文行、照片辨识原文行 | 记录数量、哪个单位有记录、什么时候改过 |
| 跟进事件：取消原因 | 员工的名字（登录账号） |

**为什么不全部加密**：服务器要核对每次写入（员工不能删资料、不能冒名、只能撤回自己的记录，见 CLAUDE.md 3.5）。这要看得到「哪一条、谁写的、有没有被删」。所以结构和「谁做的」保持明文，只有描述人的文字加密。

字段清单在两处，必须一致（有测试核对）：[server/workspaceSealed.mjs](../server/workspaceSealed.mjs)、[src/data/workspaceCipher.ts](../src/data/workspaceCipher.ts)。**新增任何会写到人的字段，都要加进这两份清单**，否则服务器不会拦，资料会以明文存进去。

## 钥匙怎么运作

1. **数据钥匙**：管理员第一次设定时，浏览器随机生成 32 字节，用它加密资料（AES-256-GCM）。
2. **机构密语**：用 PBKDF2-SHA-256（60 万次）从密语推出一把「锁」，把数据钥匙锁起来。服务器只存锁住的副本、盐值和次数（`org_keys` 表）。
3. **解锁**：同事在自己的装置输入一次密语，浏览器下载锁住的副本、在本机解开。解开的钥匙存在这部装置的 IndexedDB，设为**不可导出**（网页能用它，但读不出钥匙本身）。**登出或登录过期就清掉**，下次要重新输入。
4. **恢复码**：就是数据钥匙本身，52 个字元（13 组 × 4）。只在设定时显示一次，要抄下或打印交给机构负责人。忘了密语时，用恢复码可以解锁并设新密语。

**密语和恢复码都丢了，服务器上的资料永久打不开**，我们也救不回来。这是「我们看不到」的代价，要在合作意向书里写清楚。

### 细节（给审核代码的人）

- 每个值的随机数（nonce）由 HMAC(值的位置 + 内容) 推出，不是随机：同一个值每次加密结果一样，服务器逐条比对时「没改」仍是「没改」。代价是服务器看得出某一条的某个字段有没有改过——这从版本号本来就看得出。
- 值的位置（集合、记录 id、字段名）作为附加数据（AAD）绑进密文：把一条的密文搬到另一条或另一个字段，解不开。
- 服务器对敏感字段做「必须是 `enc:v1:` 开头」的检查（空值例外），浏览器漏加密或有人手工发请求，都会被 `400` 拒绝。
- 换密语只是重新锁一次同一把数据钥匙（`keyId` 不变），资料不用重新加密，恢复码不变。
- 换成另一把数据钥匙（`keyId` 变）会让现有资料打不开，所以服务器**只在工作区是空的时候**接受（否则 `409`）。

## 开启步骤（管理员）

1. 「設定 › 資料加密」：输入机构密语两次 → 抄下恢复码 → 勾选「我已抄下」→「啟用這句密語」。
2. 「設定 › 功能開關」：打开「跨裝置同步」。
3. 同事打开工作台，顶部会出现「輸入機構密語」，输入一次即可。

没设密语就打开同步：服务器拒绝存任何东西，工作台显示「尚未设定机构密语，资料只留在这部装置」。

## 交接给机构（方案二，2026-10-19 决定）

测试阶段由 Oscar 先设一句测试密语。交给机构时：

1. 在同步开着的状态下，把工作区导出 Excel 备份，然后清空工作区（只有管理员能做；同步关着时只会清空这部装置）。
2. 机构负责人在「設定 › 資料加密 › 換一把新密鑰（交接用）」设定自己的密语，自己抄下新的恢复码。
3. 旧密语和旧恢复码全部作废。之后开发团队不知道密语，也没有恢复码。
4. 需要的话，再把 Excel 导回去（会用新钥匙加密后上传）。

只「更改密语」不够：恢复码不变，知道旧恢复码的人仍能解开。所以交接要用「换新密钥」。

## 没有覆盖的地方（诚实说明）

- **装置本机的副本没有加密**。浏览器 localStorage 里的工作副本是明文，拿到没锁屏的手机或电脑就能看到。要靠装置锁屏；以后可以再加本机加密。
- **导出的 Excel 是明文**，这是设计：机构要能直接打开。导出的文件要按机构的资料规定保管。
- **照片回录**另有开关：照片会送到 Azure 辨识，那一段不在这个加密范围内。
- **网页程序本身**由我们部署。理论上部署者可以改程序偷密语；这是所有网页加密的共同限制。缓解：代码公开、部署留记录。
- 服务器看得到结构和统计：哪些大厦、多少单位、哪个单位有记录、谁录的、什么时候。
