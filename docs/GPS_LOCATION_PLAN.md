# GPS 装置定位功能计划与实施记录

> 日期：2026-11-21；实施及浏览器验收：2026-11-22
> 状态：已实施；真实 iOS／Android 硬件仍按第 7 节人工验收。
> 范围：首次授权、个人设置开关、新增大厦搜索候选的距离加权，以及每次进入工作台／刷新后的初始地图定位。

## 1. 目标与范围解释

为现场同事提供可自主控制的装置定位能力：

1. **首次进入时询问**：每个账号在每台装置、每个浏览器第一次进入已登录的工作台后，看到一次定位说明；只有当事人点击同意后，才调用浏览器定位权限。
2. **个人设置可开关**：用户点击同意后，个人「設定」里的「裝置定位」开关自动打开并进入请求状态；浏览器明确拒绝时回退为关闭。管理员和员工都能自行打开、关闭，并通过刷新自动重试，不由机构管理员统一决定。
3. **定位辅助新增大厦**：功能开启且取得可用位置后，新增大厦的名称／地址搜索候选在保留文字相关性的前提下，按装置距离加权排序，并显示直线距离。
4. **进入时定位地图**：每次完整进入工作台或刷新页面时，若功能已开启，取得位置后以装置为中心显示适当范围；定位更新不能持续抢走地图镜头。

本文将需求里的「增加楼房时」落到现有的**「新增大廈 → 大廈名稱或地址搜尋」候选列表**。本期不默认重排工作台全部既有大厦，也不改变记录表单；如果实际需要的是「记录时选择既有大厦」列表，应在实施前确认，并复用本文的同一套距离与排序规则另开小改动。

### 不在本期范围

- 后台持续追踪、移动轨迹、到访路线、地理围栏或离开页面后的定位。
- 用 IP 地址推测位置；浏览器不支持或拒绝定位时不伪造位置。
- 自动新增大厦、自动选择搜索候选、自动修改大厦坐标或轮廓。
- 步行距离、路程时间或导航；本期的距离是两点之间的**直线距离**。
- 把定位同步到其他装置，或把个人定位开关做成机构／平台功能开关。

## 2. 现有实现与约束

- `src/auth/SessionGate.tsx` 同时承载登录后的工作台与 `AccountPanel`，定位状态需要由两者共享；不能在地图组件里另开一套权限状态。
- `src/auth/AccountPanel.tsx` 的密码、登录状态对所有角色可见，管理员功能区从后面的管理员条件开始。个人定位开关必须放在所有角色可见的区域，不能放进平台／机构功能开关。
- `src/map/MapScene.tsx` 初始化使用 `DISTRICT_CAMERA`，无选楼时由 `frameDistrict` 恢复街区总览；选楼、新增大厦和形状编辑已有自己的镜头行为。定位只能参与**初始无选楼总览**，不能覆盖这些交互。
- `src/map/AddBuildingPanel.tsx` 已用 `searchTicket` 绑定搜索请求与结果；距离排序必须在结果回来之后、展示之前完成，不能破坏旧请求失效规则。
- `src/map/placeSearch.ts` 的 `PlaceResult` 现有 `id/name/address/lng/lat/relevance/distanceMetres`。服务器 `server/placeSearch.mjs` 返回归一化到 0–1 的 `relevance`，`distanceMetres` 只由浏览器按装置位置补入；不能在前端按名称另写一套匹配规则。
- 地址搜索是由平台管理员控制的机构功能 `placeSearch`，与个人定位不同。个人定位不新增服务器功能开关，也不能因为机构关闭地址搜索而阻止地图初始定位。
- 新增大厦继续沿用 `docs/GEOCODING.md` 的「搜索 → 人选候选 → 确认位置／轮廓 → 原有 `addBuilding`」路径。定位只是排序依据，不是业务坐标来源。
- 浏览器 Geolocation API 通常只在 HTTPS 或 localhost 的安全上下文可用。这里取得的是浏览器提供的装置位置，可能来自 GPS、Wi-Fi 或网络，不应在界面上承诺一定是卫星 GPS。
- 地图使用外部底图服务。即使精确坐标不发给自家服务器，以附近位置为中心仍会让地图服务按显示范围请求图砖；隐私说明不能使用「位置完全不离开装置」这种绝对表述。

## 3. 用户体验设计

### 3.1 首次授权说明

时机：已完成登录、当前账号的工作台可以进入之后。不要在登录页、设置密码页或尚未认证时请求定位。

实际繁体中文文案与按钮：

- 标题：「要開啟裝置定位嗎？」
- 内容：分别说明新增大厦搜索会按地址相关程度及装置远近排序，以及进入／刷新后地图会以目前位置为中心适当放大。
- 隐私：「位置只在這個頁面使用，不會儲存到工作區，也不會隨地址搜尋送出。」同时保留地图图砖说明。
- 主按钮：「開啟定位」
- 次按钮：「暫不開啟」

行为：

- 点击「開啟定位」后才调用 `navigator.geolocation`，由浏览器显示原生权限询问；不能用应用说明框代替浏览器授权。
- 点击「開啟定位」后立即保存个人偏好 `enabled: true`，设置页开关打开并显示「正在取得位置」，随后调用浏览器定位。浏览器明确拒绝时回退为关闭；暂时超时或没有结果时保留用户的选择，刷新会自动重试，不把技术故障写成拒绝授权。
- 点击「暫不開啟」只记录已经询问和保持关闭，不调用定位，不反复弹出；之后可在设置页主动开启。
- 浏览器拒绝权限时保持应用开关关闭，说明如何在浏览器网站设置中重新允许；不能由网页绕过或重置浏览器拒绝状态。
- 说明框超时、定位失败与「拒绝授权」分开处理。暂时失败不应被记成永久拒绝，也不阻断使用工作台。

### 3.2 个人设置

在 `AccountPanel` 所有用户可见的位置增加「裝置定位」区块，放在管理员功能区之外。至少包括：

- 开关及当前状态：关闭、正在取得位置、已开启、浏览器已拒绝、暂时无法定位、此浏览器不支持。
- 用途简述及「只影响这个账号在这部浏览器上的定位功能」说明。
- 开关只显示「关闭／开启」，下面另设「目前状态」，不把两者混成一行。
- 成功定位后显示「上次定位时间」和取整后的大约准确度，不默认展示完整经纬度。
- 不另设「重新定位」按钮；每次完整进入／刷新都会自动取得位置，失败时说明可检查权限、网络后刷新。
- 浏览器拒绝时的网站权限设置指引；非 HTTPS 或 API 不存在时停用开关并说明原因。

关闭时立即停止监听、清除内存里的位置与地图装置标记、移除距离提示，搜索恢复原有顺序，之后不再自动居中。当前已经展示的地图可以停留原地，不必强行移回默认街区。

### 3.3 定位生命周期

- 首次同意、设置页打开开关、已开启状态下的完整页面进入／刷新：主动取得一次位置。
- 页面可见且开关开启时，用 `watchPosition` 更新内存位置，供之后的新搜索使用；页面隐藏、开关关闭、登出或账号切换时停止监听。
- 每次刷新都重新向浏览器取得位置，不从 localStorage 恢复旧坐标。浏览器自己的短时缓存可以使用，但界面要显示定位时间。
- 新搜索以结果返回时的一次位置快照排序；同一份结果已经显示后，不随每次定位更新在用户鼠标／手指下反复跳动。下一次搜索再采用较新的位置。
- 只有初次有效定位可用于当前这次页面进入的自动居中。后续 watch 更新不能反复移动地图。

## 4. 技术设计

### 4.1 状态与存储边界

建议增加一个认证后共享的 `DeviceLocationProvider`／hook，由 `SessionGate` 的工作台与设置分支共同使用，并由 `App` 在工作台就绪后控制首次说明。浏览器 API 通过小型适配器注入，方便测试，不在各组件分别调用。

个人偏好按**账号 + 当前浏览器**保存，例如独立 key：

```text
careflow-atlas.account.<accountId>.device-location.v1
```

不能只按机构保存，否则同机构不同同事会互相开关。建议持久化内容仅为：

```ts
{
  version: 1;
  prompted: boolean;
  enabled: boolean;
}
```

`prompted` 与 `enabled` 必须分开，才能区分「尚未询问」「用户暂不开启」「用户曾同意但暂时定位失败」。读取到损坏或未知版本时安全回退为关闭，不影响工作区。存储不可用时可以允许本次会话使用，但要提示刷新后不会记住，不能伪称已保存。

运行时另维护：

```ts
{
  status: 'idle' | 'requesting' | 'ready' | 'denied' | 'timeout' | 'unavailable' | 'unsupported';
  fix?: { lat: number; lng: number; accuracy: number; observedAt: number };
  requestGeneration: number;
}
```

- `fix` 只放内存，不进入 localStorage、工作区 snapshot 或账号数据库。
- 坐标必须有限且经纬度范围合法，`accuracy` 必须有限且大于零。
- 账号切换、登出、关闭开关及组件卸载时使旧请求失效；无法取消的 `getCurrentPosition` 晚到回调必须用 generation 丢弃，不能写到另一个账号的状态。
- 浏览器 Permissions API 可用于辅助显示权限变化，但不能作为唯一依赖；最终以实际定位成功／错误和用户的应用内选择为准。

建议首版定位参数为 `enableHighAccuracy: true`、`timeout: 10_000`、`maximumAge: 60_000`，在真机测试后再调整。超过 5 分钟的内存位置标为过期，不再用于新搜索排序或自动居中；准确度差于 500 米的定位只显示状态，不用于楼宇级排序和自动居中，避免把整个街区误当精确位置。

### 4.2 距离计算

在 `src/domain/` 增加浏览器无关的纯函数，采用 Haversine 公式计算米数，并集中处理：

- 非法坐标、缺失定位、过期或低准确度定位；
- 距离格式化，例如「直線約 85 米」「直線約 1.2 公里」；
- 相同距离的稳定排序；
- 排序所用的相关性、距离权重与阈值常量。

不新增第三方定位或距离依赖。距离只用于展示和排序，不据此合并大厦、判重或修改既有 15 米疑似重复规则。

### 4.3 新增大厦候选的加权排序

流程保持为：

```text
用户输入名称／地址
  → 现有 /api/place-search?q=... 请求（不带装置坐标）
  → 服务器沿用文字匹配和门牌收窄，并返回相关性元数据
  → 浏览器取得该次结果对应的一份有效定位快照
  → 本地计算文字相关性 + 距离的综合分
  → 展示候选及直线距离
  → 用户点击候选，继续现有人工确认与新增流程
```

建议首版使用可测试、可解释的固定起点：

```text
proximity = 1 / (1 + distanceMetres / 300)
score     = 0.70 × relevance + 0.30 × proximity
```

- `relevance` 归一化到 0–1，来自服务器**已有的**名称匹配／前缀匹配结果，不是 ALS 原始分数，也不是前端猜测。
- 现有服务器先剔除不符合文字和门牌条件的候选，这一步不变；距离不能把本来不匹配的地址重新加入结果。
- 权重和 300 米距离尺度集中在领域常量中，首版只是待真机验收的初始值，不宣称是最优权重。调整时必须同步排序测试和本文。
- 同分沿用服务器原顺序；无有效定位、定位关闭、定位过期或准确度不足时，完整保留现有顺序且不显示距离。
- 服务端需把已有的相关性元数据加入 `PlaceResult` 并由浏览器边界校验。若旧响应没有该字段，保留原顺序，不补造分数。
- 搜索 query、request ticket、取消与错误处理保持原语义。装置坐标不得出现在 URL、请求体、服务器日志或 ALS／HA 上游请求中。

界面在候选名称／地址下增加「直線約 X」，让排序原因可见。排序不会自动选择第一项，也不会自动填坐标或创建大厦。

### 4.4 每次进入／刷新后的地图居中

`App` 只把当前内存里的定位传给 `MapScene`。地图与定位可以任意先后就绪，使用每次挂载只消费一次的状态协调：

1. 地图先按现有默认街区加载，避免白屏或长期等待定位。
2. 当 `map ready` 与首个有效 `fix` 都具备，且本次进入尚未消费过定位时，以装置为中心执行一次 `flyTo`。
3. 首版采用 zoom 17.2，保留现有 pitch／bearing 与 `mapInsets`；手机向上偏移最多 120px，避开底部列表。误差超过 500 米的定位不会进入这一步，避免把街区级位置当成楼宇级位置。
4. 尊重现有 reduced-motion 设置；定位失败、超时、过期或准确度不足则维持 `frameDistrict`。
5. 若定位返回前用户已经选楼、开始新增／编辑、拖动或缩放地图，取消本次自动居中，用户操作优先。
6. 大厦数据 `extentKey` 更新、楼层展开、返回总览和后续定位更新不重新消费初始定位。选楼与新增候选的现有镜头逻辑始终优先。

地图显示当前装置位置点，不含账号、人员或备注。关闭定位、位置过期或误差超过 500 米时移除。此标记不是大厦数据，也不进入 GeoJSON 导出或业务 snapshot。

## 5. 隐私、安全与故障回退

### 数据边界

- 精确坐标、准确度与定位时间只保存在当前页面内存；本地只保存是否询问、是否开启两个偏好。
- 不写入 `OutreachSnapshot`、Excel／JSON 导出、服务器工作区、操作审计、内容日志、AI 请求或地址搜索请求，因此不需要也不应加入工作区 `SENSITIVE_FIELDS`。
- 不为了调试打印坐标；错误日志只记录错误类别和状态。
- 不在后台或锁屏后持续追踪，不保存历史位置列表。
- 地图供应商仍会按地图范围收到图砖请求及通常的网络元数据，浏览器供应商的定位行为由其自身政策决定；设置说明要如实保留这一点。

### 回退原则

| 情况 | 行为 |
| --- | --- |
| 用户暂不开启或主动关闭 | 不调用定位；原搜索顺序、默认街区镜头，其他功能不受影响 |
| 浏览器拒绝权限 | 应用开关保持／改为关闭，显示浏览器设置指引，不反复弹窗 |
| 非安全上下文或 API 不支持 | 显示原因；从未开启时不能打开，已保存为开启时仍可关闭；不使用 IP 定位替代 |
| 超时、暂时不可用、无网络 | 保留工作台；刷新自动重试，不能误报成用户拒绝 |
| 定位过期或准确度差于 500 米 | 不加权、不自动居中，状态说明该位置不会用于排序或放大 |
| 地图加载失败 | 定位状态与列表仍可用，不因为镜头失败阻断记录流程 |
| 账号切换或旧请求晚到 | 丢弃旧位置与旧回调，不跨账号显示 |

## 6. 实施内容

1. **领域规则**：`src/domain/deviceLocation.ts` 负责坐标校验、有效期、Haversine 距离、70／30 加权和距离格式；`src/domain/deviceLocation.test.ts` 覆盖精度与边界。
2. **个人偏好与状态机**：`src/location/locationPrefs.ts`、`locationMonitor.ts`、`DeviceLocationProvider.tsx` 负责每账号本地偏好、首次／刷新自动定位、前后台监听、登出清理和 StrictMode 回调失效。
3. **授权与设置 UI**：`DeviceLocationConsent.tsx`、`DeviceLocationSettings.tsx`、`deviceLocation.css`；设置页开关与「目前狀態」分开，没有「重新定位」按钮。
4. **地址搜索**：`server/placeSearch.mjs` 返回相关性；`placeSearch.ts` 校验；`AddBuildingPanel.tsx` 仅在浏览器加权。`searchBox.ts` 的本地 `restored` 事件在关闭定位或位置失效时恢复同一批结果，不复活旧网络请求。
5. **地图**：`App.tsx` 传入内存 fix；`MapScene.tsx` 每次挂载最多初始居中一次、显示／移除装置标记，选楼和用户操作优先。
6. **会话边界**：`SessionGate.tsx` 让设置页与工作台共享同一账号的 provider；`AccountPanel.tsx` 对所有角色显示个人定位，不复用平台功能开关。

4. **手机权限**：分别测允许、拒绝，以及 iOS Safari／Android Chrome 设置中撤销权限；系统返回桌面再回前台时不出现重复说明或失控监听。
5. **地图**：首次定位只居中一次、保留周边；手机底部列表不遮住位置点；选楼、拖动、新增、返回总览不被后续定位抢镜头。
6. **新增大厦搜索**：近距离但文字仍相关的结果合理前移并显示距离；watch 更新不打断当前手指操作；关闭或低精度后恢复服务器顺序。选中结果仍须人工确认，不自动建楼。
7. **账号与数据边界**：管理员、员工各自设置；换账号不沿用偏好；坐标不出现在工作区、Excel／JSON、ALS 查询或账号操作记录。

实现与浏览器自动化验收已完成；真实硬件、实际 HTTPS 部署域名和真实位置体验按上述清单验收后才能视为现场验收完成。

## 8. 完成定义

- 三个原始需求均有可操作的界面和自动化／触屏浏览器验收记录；真实 iOS／Android 硬件验收单列，不冒充已完成。
- 定位关闭、拒绝、失败或不支持时，现有工作台、搜索与新增大厦流程完全可用。
- 距离只影响新增大厦候选的显示顺序，不替代文字匹配、不自动写业务数据。
- 地图自动居中只在每次页面进入发生一次，任何用户交互都不会被后续定位更新打断。
- 没有装置坐标进入工作区、导出、地址搜索、AI、审计或自家服务器日志，隐私说明同时保留地图图砖与浏览器定位服务的真实边界。
