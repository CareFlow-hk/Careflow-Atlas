# Architecture

## System shape

```text
synthetic XLSX / fixture
        |
        v
workbook adapter + validation
        |
        v
provisional domain snapshot
        |
        v
repository + localStorage adapter
        |
        v
Zustand workspace store
        |
        +------> React workflow panels
        |
        +------> map view model ------> MapLibre renderer
```

The application is client-side React 19 and TypeScript, built with Vite 6. Zustand owns the shared workspace selection and imported snapshot. Components do not embed fixture-specific records.

## Domain and temporal semantics

[src/domain/types.ts](../src/domain/types.ts) separates buildings, floors, units, people, households, household membership, residence, membership, visits, and observations. These types are provisional because the NGO's real forms have not been supplied.

Coverage, contact outcome, housing assessment, source, and follow-up are independent fields. The legacy workbook maps blank coverage to `UNKNOWN` with a warning; the Chinese paper workbook requires an explicit coverage choice, including unknown. Neither treats blank as `UNVISITED` or `VISITED_NO_FINDING`. Derived building/floor summaries respect scope so a single unit event cannot declare an entire building complete. Unknown totals remain unknown and do not produce a percentage.

Observations carry an occurrence date or timestamp and an exact recording timestamp. Paper-only dates remain dates; relative timing stays verbatim in follow-up notes. Derived state uses occurrence time first and recording time to break ties; a stale building or floor event cannot override newer unit work. Counts describe distinct recorded locations rather than event volume. Saving appends an immutable event. A repeated event ID is accepted only when its content is identical; a conflicting reuse is rejected. Corrections exclude superseded events from coverage and follow-up candidates. Forks are rejected even if their intermediate events have been corrected again. Closure references resolve across the task correction chain; only effective closure versions count. Changes to follow-up or closure relationships require a correction reason.

## Import and persistence

[src/data/workbookImport.ts](../src/data/workbookImport.ts) parses `.xlsx` bytes with SheetJS. It accepts only the deliberately designed synthetic workbook contract, requires synthetic metadata, validates headers, values, dates, IDs, and entity relationships, and returns no snapshot when errors exist. Unknown sheets, populated unmapped columns, duplicate headers and formulas block import. Blank legacy coverage remains an explicit warning. Numeric cells are read without display rounding to preserve coordinates. All readers share a 5 MB / 5000 rows / 64 columns limit.

The workbook is an import shape, not the future NGO schema. [scripts/generate-demo.ts](../scripts/generate-demo.ts) generates the bundled sample from the domain fixture.

[src/data/repository.ts](../src/data/repository.ts) is the data-access boundary used by the UI. Its `PersistenceAdapter` currently uses browser `localStorage`. [src/domain/schema.ts](../src/domain/schema.ts) uses Zod to validate every collection, calendar and instant fields, duplicate IDs, parent chains, and follow-up resolution references before a snapshot is read or written. A future remote repository can replace the adapter without moving storage logic into components.

The UI merges imports after a visible review step. `workflowWorkbook.ts` handles the Chinese six-sheet paper/Excel contract; `workflowMerge.ts` unions records by ID, skips duplicates, preserves newer local history and checks editable person/building fields against the export baseline. Conflicts block the entire merge. The store reads persisted data again at confirmation before validation and one write. Deleting Excel rows never deletes existing records. The legacy English workbook remains supported through conservative merging. The UI caps selected workbook files at 5 MB. Export provides the six-sheet Excel workbook or a complete JSON backup; the Excel archive sheet retains all domain relationships and history. See [EXCEL_WORKFLOW.md](EXCEL_WORKFLOW.md).

## Map and selected building

[src/map/MapScene.tsx](../src/map/MapScene.tsx) uses MapLibre GL JS 6.4.1. OpenFreeMap Positron supplies the real OSM-based basemap and surrounding building extrusions when available.

The selected-building layer is independent GeoJSON generated by [src/map/mapModel.ts](../src/map/mapModel.ts). MapLibre renders both target buildings and separated floors with native `fill-extrusion`. Floor base/height animation and picking therefore share the same camera and renderer. The map renderer receives only spatial IDs and summaries; people and observation notes do not enter the map model.

The four original and sixteen expanded demo footprints are selected from the same OpenFreeMap/OpenMapTiles building geometry as the basemap, with provenance in `src/data/demoGeometry.json` and `src/data/districtGeometry.json`. Names, identity associations, heights, floors, and units remain synthetic and illustrative. Selecting a target triggers a controlled camera transition and automatically expands declared floors. Expanding floors animates only vertical gaps, using the exact same ground ring. District bounds control overview framing; dense labels collapse to accessible location dots. Reduced-motion preferences disable the long camera and floor animations.

If the map style or WebGL fails, the list, building detail, history, and record form remain usable. Selecting an unsupported context building produces a clear no-demo-records message.

## Implemented boundaries

The repository has seams for workbook import, persistence, and map presentation. The Node/SQLite account service provides login, account roles, sessions and account auditing. The photo service extends that authenticated server with Azure Responses recognition; browser-side image preparation and account-scoped IndexedDB drafts feed a human review step, then a single validated append updates the existing workspace. See [PHOTO_INTAKE.md](PHOTO_INTAKE.md) for the provider contract, configuration and retention boundary. There is still no shared production business database, tenancy, offline sync, government-data integration, real Excel migration, or real approval workflow.

Production work must add an authenticated server-side data boundary before any real person, household, phone, address, membership, or outreach history is stored. It must also define conflict handling, audit, retention, deletion, backup, permissions, and provider governance with the NGO.

## Spatial focus and operating limits

Floor labels are projected from each slab’s geographic coordinate and altitude through MapLibre’s current view matrix. Their horizontal offset accounts for the actual footprint size. Loaded OSM multipolygons are split into individual footprints; shells whose interiors overlap the outreach footprint bounds are excluded in both overview and focus, avoiding duplicate buildings. Focus lowers foreground context in a corridor relative to the live view centre and bearing. Camera move/resize events classify both context and other outreach buildings into two states: source height or a minimum of 2 metres (shorter structures retain their height). Enter at zoom 17.1 and pitch 34°; exit at zoom 16.8 or pitch 28°. These hysteresis thresholds and a 5-metre corridor exit margin prevent flicker, and never determine an intermediate resting height. A changed target starts a 420 ms cubic animation through feature state; it finishes independently of camera motion and does not restart while its target is unchanged. Reversal continues from the current animated height; reduced motion snaps immediately. Geometry is not rebuilt per animation frame; selected buildings and floor slabs stay intact. Overview compresses background heights to 35%, capped at 24 metres, to distinguish the synthetic outreach targets. These are presentation treatments, not a corrected survey or authoritative building model.

`alignDemoBuilding` upgrades only the exact legacy bundled demo identity/address/coordinate combinations that lack a supplied footprint. Repository reads apply this migration in memory; normal saves persist it. Existing observations and relationships are preserved, and independently imported/edited locations or explicit footprints are left untouched. The demo workbook carries an optional `footprint` JSON column; the importer validates it against the existing domain schema.

The map scene loads on demand. The current recognition panel statically imports the Excel reader, so the Excel chunk loads at startup. The map remains an optional network/WebGL dependency; local records are not an offline tile cache. The optional WebMCP surface exposes synthetic coverage summaries and validated building navigation, with record creation and import still handled through the visible UI.

## Recognition preview boundary

The five W0 formats remain a closed list. The three guessed templates have no write parser. Manual mapping changes invalidate the pending parsed snapshot and its merge preview; users must reconcile the source workbook and reload it before importing. Candidate or ambiguous mappings cannot authorize a write. The recognition table does not rewrite workbook values or approve a schema migration.
