# 设定界面的角色隔离

2026-11-01 起草。目标：每一层界面上，同事看不到自己做不了的操作；功能停用时，对应配置不要挂在员工和机构管理员眼前。

2026-11-01 拍板：6.1 保留机构密语、6.2 采选项 1（按钮改名「助手」）、6.3 结构性操作留一句「請聯絡管理員」。已开工。

## 1. 决定

- **只隐藏「操作」，不隐藏「数据」。** 机构内不做行级隔离是已定边界（CLAUDE.md 第 2 节），员工看得到全机构的住户与记录是设计，不是漏洞。任何想隐藏数据的需求另开决策。
- **主战场是设定页。** 其他界面「已经藏对」的不再动，只补不一致的地方。
- **功能停用时，对应配置整块不渲染**（员工与机构管理员都一样）。见第 5 节。
- 隐藏是实现层的礼貌，**不是权限**：服务器仍然逐条判定（CLAUDE.md 第 3.5 节），隐藏与 403 必须同时成立。

- **机构管理员能看到自己无权切换的三个开关，带完整说明和只读勾选框**，看起来像坏了。

## 4. 能力表

新增 `src/app/capabilities.ts`，把角色翻成布尔值，取代现在散落的判断：

```ts
export function capabilities(role: 'ADMIN' | 'MEMBER' | undefined) {
  const admin = role === 'ADMIN';
  return {
    mayRemoveStructure: admin,   // 楼层 / 单位 / 劏房
    mayClearWorkspace: admin,
    mayManageAccounts: admin,
    mayWithdrawAny: admin,
    mayWithdrawOwn: true,
  } as const;
}
```

- 现有 `canDeleteStructure={workspace.role !== 'MEMBER'}`、`canWithdrawObservation(..., role === 'ADMIN')` 改为读这张表。
- **规则只认 `server/workspaceAccess.mjs` 那一份**，不另写一套。加一个对照测试：能力表每一项与服务器判定在同一输入下结论一致，防止两边漂移（CLAUDE.md 第 6 节）。
- 表里不放「数据可见性」——那不在本计划范围。

## 5. 功能停用时隐藏什么

规则：**开关关闭 = 不渲染；开关开启但对当前账号只读 = 渲染成只读并说明由谁决定。** 两者不能混。

| 开关 | 关闭时 |
| --- | --- |
| `photoIntake` | 顶栏按钮已隐藏；设定页无对应区块（现状已符合） |
| `workspaceSync` | 设定页「机构密语」整块不渲染（待定，见 6.1） |
| `aiAssistant` | 设定页「AI 助手」区块不渲染；「功能开关」里不列该项；顶栏按 6.2 处理 |

服务器端不受影响：开关关闭时接口本来就拒，隐藏只是别让人对着死按钮点。

## 6. 已拍板（2026-11-01）

### 6.1 机构密语在同步关闭时保留

同步是由**平台管理员**打开的，而机构密语要由**机构管理员**先设好。藏起来会让机构干等一轮来回，所以同步关闭时仍显示「机构密语」，并在面板上写明「同步尚未开启，设定后等平台开启即可使用」。

这一条是对第 5 节「停用就不渲染」的**明示例外**，只针对机构密语：它是机构自己的资料准备，不是平台功能的使用入口。

### 6.2 顶栏按钮改名「助手」

2026-11-01 原本的做法是**保留按钮、改名「助手」**：对话框里还挂着**本地计算的任务提醒**（不经过 AI，开关关着也能用），所以按开关隐藏会连任务清单一起没了。

2026-11-02 改定：**`aiAssistant` 关闭时整个按钮不渲染**。理由是留一个名字含糊的「助手」按钮，同事点进去才发现 AI 不能用，比直接看不见更差；而任务清单仍有入口——左侧「待跟進」分页按同一套记录计算，不依赖 AI，也不经过服务器。

因此：

- `App.tsx` 只在 `snapshot && aiAssistant` 时渲染顶栏按钮。
- 对话框仍保留 `aiEnabled=false` 的降级分支（测试直接渲染组件时仍覆盖）：它不是权限，只是**万一被别处调用**时不至于报错。
- 服务器端不受影响：AI 关闭时 `/api/ai/assist` 本来就拒。

### 6.3 结构性操作留一句「請聯絡管理員」

结构编辑提示里保留现有那句「員工不能刪除樓層、單位或劏房……請聯絡管理員」，避免同事以为系统坏了。清空工作区这类整块功能则直接不出现。

## 7. 不做

- 行级数据隔离、按人筛选记录。
- 「申请权限」流程。
- 把隐藏当成权限：服务器判定不动。
- 重写设定页样式或信息架构。

- 用 `MEMBER` 走一遍设定页、楼层、单位、劏房、记录：**没有任何点了会被拒的按钮**。

## 10. 实现说明

- [src/app/capabilities.ts](../src/app/capabilities.ts)：角色翻成布尔值，是界面唯一的能力来源。
  [capabilities.test.ts](../src/app/capabilities.test.ts) 把每一项当作真正的写入交给
  `server/workspaceAccess.mjs` 的 `assertWorkspaceWrite`：表里写 `false` 的，服务器必须回 `403`；
  写 `true` 的，服务器不得拒绝。改错一边，这个文件就红。
- 没有角色的路径（测试、旧演示）保留原行为：结构可删、记录仍只可撤回自己未被改动的。
- [WorkspaceAdvancedSettings.tsx](../src/components/WorkspaceAdvancedSettings.tsx) 的 `role` 改由
  登录会话传入，不再从工作区 store 读 —— 设定页本来就知道是谁在问，两个来源迟早会不一致。
- [AccountPanel.tsx](../src/auth/AccountPanel.tsx)：功能开关按 `featureKeys` 过滤，平台管理员看全部，
  机构管理员只看已开启的；一项都没有时不渲染整块。AI 助手的状态面板同样只在开关开启时渲染。
- [App.tsx](../src/app/App.tsx) 顶栏按钮只在 `aiAssistant` 开启时渲染（2026-11-02 改定）；
  任务提醒另有左侧「待跟進」分页，同样的记录、同样的本机计算，AI 关闭时仍然可用。
