# 大廈結構編輯（實驗）

2026-10-10 加入，開關在 `src/app/features.ts` 的 `structureEditing`。關掉只隱藏介面，已改的結構保留。

## 在大廈面板編輯

- 樓層立面右上「編輯結構 · 實驗」。點格子選單位，點樓層名稱選整層。
- 新增樓層：在頂層之上加 N 層，每層 M 個單位（A室、B室…，略過 I、O）。沿用現有樓層名稱的寫法（例如「12F」→「13F」）。
- 每層右邊 ＋ 加一個單位、－ 刪除該層最後一個**看得見**的格子（最後一組已分拆時就是最後一間劏房，不會連原單位一起刪）、✕ 刪除整層。沒有記錄的樓層或單位直接刪除。
- 點一個單位（編輯結構模式下），下面出現「刪除本單位」：刪掉這個單位，已分拆的連同它的劏房房間一起刪。規則同上，有記錄先強制下載 Excel 備份。
- **單位按字母位置固定，不因刪除而左移**：A 是第 1 欄、B 是第 2 欄……刪掉 A 後，B、C 仍留在自己的欄，A 那一欄留空。新增單位時從左邊第一個空欄補起（先補 A），字母都齊了才往右邊追加。非字母名稱的單位（「1號舖」等）先讓開字母，再放進最左邊的空欄，任何情況下都不覆蓋已經放好的格子，只跟在自己的樓層。
- **表頭跟著欄目實際內容**：一欄有字母單位就顯示該字母，沒有才顯示那欄單位的名稱（例如數字編號的大廈顯示「1室、2室、3室」而不是 A、B、C）。刪掉 B 之後 B 欄留空，不會把 C 改名成 B。
- **名稱裡的空格不構成差異**（2026-10-16 review）：讀單位字母之前，先把樓層名和單位名的空白統一。示範資料樓層寫「1 樓」、單位寫「1樓 A室」，按字面比對會令 362 個示範單位有 326 個讀不出字母——刪掉 A 之後 B、C 左移，紙本行也認不出已有的單位。讀法只有一套（[letterOf](src/domain/structure.ts)），立面欄位、＋、助手建議共用。
- **新單位沿用同一層已有的寫法**（2026-10-16 review）：名字不是拿樓層名拼出來的，是抄同一層單位的寫法（該層沒有就抄同一幢樓，樓層號換成這一層的），所以 ＋ 補回來的 A 跟被刪掉的那個寫法一致，新樓層的單位也跟同一幢樓其他層一致。樓層名用來拼單位名會產生「1 樓 A室」夾在「1樓 B室」中間的一層兩種寫法，帳目和 Excel 匯出也一樣看得見。沒有可抄的（全新大廈）才用樓層自己的寫法。
- **刪除會帶走記錄時，先備份才可以刪**（2026-10-15 review 第 2 條）：確認條列出會消失的位置與筆數，「下載當前 Excel 備份」成功後「確認刪除」才可按。下載失敗（或瀏覽器未接手）就不能刪，只會顯示原因。劏房合併（減少間數）去掉的房間若有記錄，走同一套。這是「觀察事件只追加」的唯一例外，見 `CLAUDE.md` 第 4 節。
- **確認條只列立面上看得見的位置**（2026-10-16 review）：已分拆的單位在立面上不畫，只畫它的劏房房間，所以確認條把「看得見的房間」和「立面上沒有的原單位」分開寫、各報各的筆數；原單位不在這次刪除裡，它的記錄就不算進去。
- 分拆為劏房：選一個單位，填間數，得到 A1室、A2室…（`parentUnitId` 指向原單位）。原單位保留，分拆前的記錄仍在它名下；立面上該欄只顯示劏房，房間在同一格內平分，欄寬不變。
- 確認無劏房：可批量；記錄操作人及時間（`noSubdivision`）。這是結構標記，不是到訪記錄，不改顏色。已分拆的單位不能確認；分拆會取消原有確認。

## 照片回錄的助手建議（semi-agent）

- 紙本寫的位置在結構裡沒有（例如「5樓 B1室」），而且寫法清楚（數字樓層、一個英文字母、可帶房號），核對頁會列出要做的步驟：新增樓層、新增單位、分出劏房。
- 同事按「套用」才會改結構，並選取該單位；同一批其他寫着同一位置的記錄一併對上。這一步不會新增到訪記錄，記錄仍要逐筆核對後才入庫。
- 寫法不清楚（「地下」「後座」等）不提出建議，不猜。
- 「試用示範紙本」在開啟此功能時多一行未有的劏房，用來示範。

## Excel

`parentUnitId`、`noSubdivision` 隨「關聯封存」匯出及匯入。Excel 匯入「紙本回錄」遇到未有的位置，暫時仍報 UNKNOWN_LOCATION，未接助手建議。

## 楼层命名

新楼层接着最高一层有数字的楼层名往上数，不按内部层号：地下／1樓／2樓 之上是「3樓」。空楼层借用同幢的单位写法时，用该层名字里的数字；「地下」这类没有数字的楼层，直接用楼层名。纸本写「1樓」时，找名字是「1樓」的那一层。
