# 大廈結構編輯（實驗）

2026-10-10 加入，開關在 `src/app/features.ts` 的 `structureEditing`。關掉只隱藏介面，已改的結構保留。

## 在大廈面板編輯

- 樓層立面右上「編輯結構 · 實驗」。點格子選單位，點樓層名稱選整層。
- 新增樓層：在頂層之上加 N 層，每層 M 個單位（A室、B室…，略過 I、O）。沿用現有樓層名稱的寫法（例如「12F」→「13F」）。
- 每層右邊 ＋ 加一個單位、－ 刪除該層。有記錄的樓層或單位不能刪除。
- 分拆為劏房：選一個單位，填間數，得到 A1室、A2室…（`parentUnitId` 指向原單位）。原單位保留，分拆前的記錄仍在它名下；立面上該欄只顯示劏房，欄寬按間數加闊。
- 確認無劏房：可批量；記錄操作人及時間（`noSubdivision`）。這是結構標記，不是到訪記錄，不改顏色。已分拆的單位不能確認；分拆會取消原有確認。

## 照片回錄的助手建議（semi-agent）

- 紙本寫的位置在結構裡沒有（例如「5樓 B1室」），而且寫法清楚（數字樓層、一個英文字母、可帶房號），核對頁會列出要做的步驟：新增樓層、新增單位、分出劏房。
- 同事按「套用」才會改結構，並選取該單位；同一批其他寫着同一位置的記錄一併對上。這一步不會新增到訪記錄，記錄仍要逐筆核對後才入庫。
- 寫法不清楚（「地下」「後座」等）不提出建議，不猜。
- 「試用示範紙本」在開啟此功能時多一行未有的劏房，用來示範。

## Excel

`parentUnitId`、`noSubdivision` 隨「關聯封存」匯出及匯入。Excel 匯入「紙本回錄」遇到未有的位置，暫時仍報 UNKNOWN_LOCATION，未接助手建議。
